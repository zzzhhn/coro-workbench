# 完整多声部转谱：本机回归与边界

2026-11-07。本轮目标是完整歌曲的多声部总谱。主唱清唱的识别成绩不代表该目标已经完成。

## 当前默认：声源复核与音乐记谱 v2

2026-11-07，使用用户提供的《空耳》完整录音（267.102 秒）及手工 MIDI／19 页 PDF 做开发复核。人工谱在推理前已查看，因此这是开发案例，不是未见测试集。人工谱是人声、钢琴双谱表和弦乐合奏缩编，不能据此断言原混音只含三种声源。人声 MIDI 的 GM 11 是播放音色；钢琴的两条 MIDI 轨是左右手，不是两位演奏者。Fragile、Hurt 的阿卡贝拉编配也不能用作原曲配器标签。

- 完整校对在本机模型可用时，串行运行声源分离、独立钢琴起音和人声边界检查。分离轨的谐波能量用于检查串音，不充当已校准的置信度。逐项来源、原始时间与候选记录保存，原生推理文件不覆盖。
- 默认谱保留原生音符总数。独立模型新增的 102 个补音候选单独留存，没有因为参考音覆盖增加就自动加入默认谱。《空耳》默认 2,138 音，补音候选版 2,240 音；补音版中段更拥挤，未通过可演奏性验收。
- `multiscore-rhythm-2` 区分有踏板证据的连续分解和弦手指时值与声学余音；紧凑、持续重叠的滚奏和弦用琶音记号表达，真正的分离快音保持。原始收音时间和每次变更保留。钢琴左右手按局部和弦音区判断，不再把所有中央 C 以上的左手音强制扔进右手。
- ABC／MusicXML 保留琶音记号。空的辅助谱表逐行收起，基本钢琴双谱表保留；有音符的辅助谱表不隐藏，不靠丢音减少谱表。谱面速度标记取整数，内部播放和导出仍用原速度。
- 同一 program 下已有不同 `sourceId` 的声部不再合并，缓存重建也保留身份及试听轨；解码通道不作为演奏者身份。这避免已分开的来源被重新混合，**不代表可以从完整混音自动拆出同类多位演奏者**。
- 修复解码片段起点与 token 时钟的小数精度差异，保留原始 token、通道事件和混合前证据。到达 token 上限但缺 EOS 的通道最多扩容重试一次，完整通道保持。《空耳》重跑没有减少其原有的 373 次 onset-not-found／455 次 merging-tie 记录，不能宣称这两类错误已解决。
- 另对整首去人声伴奏重跑多乐器模型，得到 2,793 音及更多弦乐候选，没有采用该结果。11 个截断通道确实恢复 EOS，但这不证明新增音符正确。

按人工谱每四小节建立 18 个连续对照片段，覆盖约 1.0～266.9 秒，逐段查看钢琴前后谱面并与 PDF 对照，另检查人声／弦乐重点段落。开头和尾奏的分解和弦写法改善，中段钢琴额外节奏线、人声短音以及弦乐类别漂移仍明显存在。全曲的每个音尚未完成听觉核对，当前工具没有可验证的直接听觉评审接口。播放链路测试不能替代听觉验收。

私有材料、逐段截图、原生结果、失败实验和两个便携工程位于本机 `evidence/konger/` 与 `data/p0-multiscore/private-konger/`，均不进入版本库。两个 `.coro` 内含完整原 MP3、钢琴／人声试听轨及 19 页参考谱；试听轨为 22.05 kHz 单声道，原始分离 WAV 另存。默认工程已在实际工作台导入、刷新恢复、选择音符，检查原录音和钢琴分轨播放推进，确认参考谱首尾页可读。**本轮仍未达到直接用于整曲排练的验收标准。**

## 历史记录：音乐节奏推断 v1

用户再次指出实际图片仍有大量碎音和异常连音后，默认整理流程已由 25 ms 内的声学时间量化，改为 `multiscore-rhythm-1` 音乐记谱推断。下方量化 v1／v2 的成绩和截图是历史记录，不能当作本轮可读性验收。

- 原始模型事件保留。默认谱本按半小节的节奏模式选择网格，连续起音联合对齐；持续声部单独推断拍点，避免被快速音群拖到细分拍点上。
- 至少两个乐器类别的稳定起音共同支持时，修正节拍检测器的共享相位偏差，各类别等权，避免密集琶音独占判断。Track00009 的六个类别共同支持提前 27.721 ms；TRIOS 不满足跨声部一致条件，不作全局修正。原拍点和修正量分别记录。
- 收音与谱面时值分开：连续短收音用断奏记号表达，极短收音保留合理休止，长音不按其他声部的每次起音切分。判断同时适用于钢琴、吉他和有连续断奏证据的管乐。
- 同起音且收音差在 40 ms 内的和弦音共同决定记谱时值，避免一颗音跨过判断阈值就拆出额外声部与碎休止。独立持续音不并入短和弦；断奏乐句的最后一音沿用前面的节奏依据，后续真实休止保留。
- 三连音需要完整三次起音模式支持，ABC 用一组括号表示。普通收音误差不再凭空产生五连音、十五连音或三十连音。
- 快速音群与持续音分层；键盘／和弦音区内重新分配声部。密集小节单独一行，保留正常字号。没有为制造干净截图而删除真实快速音群。
- 默认谱本允许改变记谱起止，因此不再声称每个边界都在原始时间 25 ms 内。每个音符的源时间、谱面时间和调整原因写入证据；固定速度、初始 4/4、同类乐器合并仍是限制。
- 现有工程可使用“重新整理总谱节奏”。`POST /api/projects/{job_id}/score-rhythm` 从缓存重建、另存新工程；当前编辑稿、原始模型和源音频保留，不重跑模型。
- MusicXML 保留写出的时值与断奏记号。MIDI 使用与工作台一致的断奏发声门限，不能把 MIDI 的短发声长度误当成谱面的短音符。

实际工作台检查了 Track00009 第 3、52 小节的密集声部和总谱、第 43～51 小节吉他伴奏、Track00010 第 13 小节伴奏、TRIOS 真人摘录的巴松全段。截图与可直接导入的工程位于 `evidence/musical-rhythm/`。这次重点检查音群是否连续、持续音是否独立、休止与断奏是否可读；不以无崩溃或音符数量不变代替这些观察。

当前音乐谱本的固定标签对照如下。用同一冻结推理缓存重新记谱，没有重跑模型或修改标签。MIDI 发声时长按工作台的断奏门限计算；它与 MusicXML 的写出时值不同。数字不能代替谱面验收，也不是歌曲整体准确率。

| 素材 | 音高＋起音 F1 | 按谱面字面时值的完整音符 F1 | 按 MIDI 断奏发声时长的完整音符 F1 | 再要求乐器类别正确 |
| --- | ---: | ---: | ---: | ---: |
| Track00009 | 81.96% | 29.07% | 74.41% | 74.29% |
| Track00010 | 80.77% | 67.95% | 67.37% | 66.34% |

Track00009 大量断奏用正常八分音符写出，因此不能用谱面长度直接匹配原 MIDI 的短发声长度。但按发声时长比较仍低于原生模型的 77.12%，另外两例也低于原生结果，不能宣称整理提高了整体音符识别准确度。原始音符与声学起止仍可另行查看。

这仍不是免校对的完整演奏总谱：模型会漏音、误报乐器，并把同类多位演奏者混到一起，部分谱表仍有额外声部。真人素材只有 18 秒，不能外推为所有真人整曲均已解决。默认推断优先常规节奏，少见切分、自由速度与复杂连音需要对照原声校对。

设计依据：[MuseScore 的 MIDI 转谱说明](https://musescore.org/en/handbook/3/midi-import)区分量化、声部、断奏和演奏偏差；[MusicXML 的 note 定义](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/note/)明确区分声音与记谱。这些原则用于设计，不是本产品准确性的证明。

## 已落地

- YourMT3+ 在隔离环境执行，整曲模式默认分析完整录音，最长 600 秒。其他模式仍为 300 秒上限。
- 保留 pinned `MT3_FULL_PLUS` 词表实际区分出的类别，包括小提琴、中提琴、大提琴等。13 个解码通道不是 13 种乐器身份；同一类别的多位演奏者仍共用复音声部。
- 多声部从原始秒数直接成谱，不再按大族群合并、删除 75 ms 以下短音、去重同格起音或截断重叠延音。分析窗口外事件另计，跨窗口尾部先裁剪；有音高音符的记谱起止与鼓起音偏移限制在 25 ms 内。鼓的谱面时值按起音节奏确定，不把模型约定的 10 ms offset 当作延音长度。
- 节拍整理重新使用原始事件，避免对已量化谱面再次取整。模型未提供可信置信度和力度，界面不伪造准确率。
- 修复密集总谱的 ABC 渲染崩溃：隐藏休止符不挂连音符／符杠锚点，低于排版库符号范围的细时值用带比例的显示符号处理。原工程、播放和 MusicXML 时值保留。桌面密集谱保持字号并横向滚动。

## 固定协议

`scripts/benchmark-multiscore.py prepare → infer → score` 依次获取混音、运行完整音频处理链、冻结预测及其 SHA-256，然后才下载逐轨 MIDI。标签不参与节拍、八度或时间偏移选择。推理使用 YourMT3+ 和 Beat This!，CPU 单线程、batch 1。

- 起音容差 50 ms，音高容差 50 cents，offset 容差为参考时长的 20% 与 50 ms 取大值。
- 完整音符 F1 同时匹配音高、起音和结束时间；另报起音、乐器类别和鼓指标。一对一匹配，未预测类别计入漏音，额外类别计入误报。
- 按训练词表映射参考 GM program，保留原始 stem 数。同类多轨聚合后仍保留每个音符，不假装区分演奏者。
- 鼓单独按原始 GM pitch＋起音计分，不为提高分数而套用宽松鼓类合并。鼓 offset 是模型约定，不作为音乐准确性指标。
- 旧量化基线重放原 `multi.py` 的族群聚合与四分之一拍量化，**不包含旧版可选的第二次节拍整理**。新旧使用同一份冻结的模型事件，不比较不同模型运行。

## 首轮本机结果（量化 v1）

下表为有音高事件的完整音符 F1，不是歌曲整体“准确率”。

| 数据 | 原始模型秒数 | 旧量化重放 | 新成谱 | 新成谱且乐器类别正确 |
| --- | ---: | ---: | ---: | ---: |
| BabySlakh Track00009，160.624 s | 77.12% | 49.82% | 76.62% | 76.54% |
| BabySlakh Track00010，181.894 s | 69.52% | 46.03% | 68.98% | 67.86% |
| 两首合计，4,786 个参考有音高事件 | 73.60% | 47.85% | 73.08% | 见本机逐类明细 |
| TRIOS lussier，18 s 真人三重奏摘录 | 60.34% | 45.61% | 59.37% | 53.53% |

两首整曲分别有 11／7 条渲染源轨，模型输出 9／6 个类别声部；这不等于恢复了 11／7 位独立演奏者。2,694＋3,648 个模型事件均进入谱面。模型推理耗时约 148.5／98.2 秒，另有解码、节拍整理和启动耗时。鼓起音 F1 为 74.81%／94.65%。

真实三重奏含钢琴、小号、巴松，模型却给出 6 个候选声部；乐器误报没有被手工删除。203 个事件均保留，原生模型推理约 12.5 秒。新成谱的无类别起音 F1 为 86.13%，带类别起音为 79.32%，加 offset 后明显下降，说明结束时间与乐器归属仍是重点。

新成谱的严格 F1 仍略低于原始秒数结果，25 ms 内的移动也可能跨过评分阈值。该边界不会被“音符数量不变”掩盖。跨片段 tie/onset 解码错误保留在证据中，未通过任意拼接同音来掩盖。

## 用户指出碎音后的修复（量化 v2）

首轮截图不通过可读性验收。能够显示、播放、导出，不能证明总谱正常。明确定位并修复了三处：

1. 排版把所有复音的起止边界取并集，再反复切分仍在持续的音，制造大量延音碎片。现在保留独立节奏线，必要时增加辅助谱表；辅助谱表不代表识别出新的演奏者。
2. 一次同音冲突会令整首歌的同音高事件全部退回 960 ticks。现在只细化相邻冲突区域，其他小节的正常量化保持。
3. 鼓的解码器 offset 被直接当作极短乐音时值。现在只约束鼓的起音，按后续敲击间隔选择常规谱面时值，原生模型事件保留在审计文件中。

未重新运行模型，使用同一份冻结事件生成独立副本。Track00009 保留 2,694 个事件，实际 ABC 符头由 5,807 降至 3,203；有音高打击乐仍为 493 个事件，生成 538 个符头。统计按唯一谱段计算，不把同一符段的字符索引别名重复计数。MusicXML 往返仍保留全部有音高事件和鼓的音高／起点／时值。源码不再把“更多切分”写成布局测试的成功条件。

v2 完整音符 F1 为 76.46%／68.71%／59.37%，三例顺序同上。前两例比 v1 略降约 0.15／0.27 个百分点；这是边界移动对严格匹配的影响，不宣称识别准确度改善。两首鼓起音 F1 仍为 74.81%／94.65%。

同曲参考 MIDI 确有约 50 ms 的高速琶音，不能删除真实快音来让谱面稀疏。当前仍有少量细网格事件和不理想的连音记法，也仍有模型误报；特别是同一词表类别混合多个源轨时，尚未恢复原谱的声部身份。**本修复不等于免校对的可演奏总谱验收通过。**

本机副本、审计、密度统计与截图位于 `evidence/notation-repair/`。旧冻结分析没有覆盖。已有分析可用以下命令另存修复副本，再从工作台“导入音乐”载入：

```bash
.venv/bin/python scripts/renotate-multi.py data/p0-multiscore/full-songs/Track00009 \
  --output output/Track00009-repaired.json
```

命令不启动模型、不读参考标签，已有输出路径会被拒绝覆盖。普通项目把参数替换为含 `project.json`、`multi-events.json`、`analysis-evidence.json` 的原分析目录即可；不会自动修改浏览器里的人工编辑草稿。

- [BabySlakh 官方 v1](https://zenodo.org/records/4603844)，CC BY 4.0。固定选压缩混音最小的两首，完整读取数据集曲目；不是截取容易的短段。按实际存在的逐 stem `MIDI/Sxx.mid` 评分，不用可能与渲染轨不同的 `all_src.mid`。[作者格式说明](https://github.com/ethman/slakh-utils#at-a-glance)。这是合成音乐，且很可能与 Slakh 训练数据重叠，只是开发回归。

- [YourMT3+ 作者实现](https://github.com/mimbres/YourMT3) 与 [论文](https://arxiv.org/abs/2407.04822)。代码与模型卡许可声明存在差异，见第三方声明。安装清单固定源码 revision 与权重 hash。
- [MuScriptor 作者实现](https://github.com/muscriptor/muscriptor) 是下一条长上下文联合转写对照路线。small 权重约 412 MB，但需 HF 账户接受使用条款；本轮没有接受条款或绕过访问限制，也没有把其宣传指标当成本机成绩。

范围下载拒绝 HTTP 200 整包回退，校验 member 名称、长度、CRC32 和 SHA-256。数据与冻结证据位于忽略目录 `data/p0-multiscore/`，导出、截图和详细来源报告位于 `evidence/`，均不随 Git 传播。矛盾的冻结证据不会被覆盖。
